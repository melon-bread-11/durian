Full-stack project guide

Build one feature from the browser to the database and back, then deploy it. Use the durian farm enquiry as an example and swap in your own feature for the next project.

A stack you can reuse

Frontend
Next.js App Router, React, TypeScript, Tailwind CSS. Next.js maps files to pages, React builds the interface, TypeScript checks types, and Tailwind styles the page.
Backend
Next.js Route Handlers on Node.js. Keep the API in the same app. Add a file named route.ts and export an HTTP method like GET or POST.
Database
Supabase Postgres + Prisma ORM. Supabase hosts the database. Prisma lets TypeScript code query it and tracks changes to the tables through migrations.
Git & hosting
GitHub + Vercel. GitHub stores the code and runs checks. Vercel can host the full Next.js app, including the API routes. GitHub Pages can host a static preview.

Follow one enquiry

In the current durian site, the enquiry form previews the submission. The API already exists, and connecting the form to it is a separate step.

Build order

  1. 1. Pick one action

    Write one sentence about who uses the site and what they can do. For the farm, a visitor can pick a durian and send an enquiry. Sketch the catalogue, the form, and the confirmation. List the data you need. In this example, it’s a Product and an Enquiry linked to that product.

    Check You can describe the first successful user journey in one sentence.

  2. 2. Scaffold and connect GitHub

    Install a supported Node.js version. Run these PowerShell commands from the folder where you keep projects. In the setup prompts, choose TypeScript, Tailwind, App Router, and the src/ directory.

    npx.cmd create-next-app@latest my-site
cd my-site
npm.cmd run dev

    Open the local URL printed in the terminal. Create an empty GitHub repo for your new app, then use a second terminal in my-site to connect it.

    Show the first Git push 
    git status
git add .
git commit -m "Start website project"
git branch -M main
git remote add origin https://github.com/YOUR-USER/my-site.git
git push -u origin main

    If the scaffold already made a commit and the working tree is clean, skip git add and git commit. If origin already exists, check it with git remote -v before adding a remote. Preview what you’re staging and keep real .env files ignored.

    Check The starter page opens locally and the starter files appear on GitHub.

    Next.js install guide · GitHub first push guide

  3. 3. Build the frontend with sample data

    Start with src/app/page.tsx and a second page such as src/app/durians/page.tsx. Put reusable cards and forms in src/components/. Store a few sample items in src/lib/sample-products.ts and your images in public/.

    Try the journey on a phone-sized screen. Give the form a submitting state, a success message, and a place to show errors. In Next.js, mark the interactive component that uses browser state or event handlers with "use client".

    Check You can try the whole journey using sample data.

    Next.js server and client components

  4. 4. Create the database and API

    1. Create a Supabase development project. When it’s active, open Connect → Session pooler on port 5432. Put the connection string in your local .env under DATABASE_URL.
    2. Use the Prisma setup guide for your installed version. The durian app uses Prisma 7 with the PostgreSQL adapter. Define the models in prisma/schema.prisma and keep Prisma in a server-only module such as src/lib/db.ts.
    3. On a fresh development database, create and apply a migration with npx.cmd prisma migrate dev --name init, then run npx.cmd prisma generate. migrate dev requires a shadow database to replay migrations safely. If hosted permissions block it, configure a separate development shadow database or generate the migration against local Postgres. When the migration already exists, apply it with npx.cmd prisma migrate deploy.
    4. Build GET /api/durians to list products and POST /api/enquiries to create an enquiry. Validate incoming fields on the server, check that the product can accept enquiries, and return success after the insert.

    Keep DATABASE_URL in server-side environment variables. Commit an .env.example with placeholders so another developer can see which variables to set.

    Check The local GET endpoint returns a database-backed catalogue and a test POST creates a row you can see in Supabase.

    Supabase connection guide · Prisma 7 setup · Prisma shadow database guide · Next.js Route Handlers

  5. 5. Wire the frontend to the backend

    Populate the catalogue with the saved product IDs. Submit the form with fetch("/api/enquiries", …) using POST and a JSON body. Include productId, customerName, and phone. Read the response and show either confirmation or an error.

    • Valid submission → confirmation and one new database row.
    • Missing phone or unavailable product → a clear error and no row.
    • Request fails → keep the entered values so the user can retry.

    Check A test enquiry travels from the browser to the database without opening the dashboard to enter it manually.

  6. 6. Deploy and test the live URL

    1. Run your tests and npm.cmd run build before pushing. Add GitHub Actions checks once the commands work locally.
    2. Import the repo into Vercel and choose the folder containing package.json as the project root. Set server environment variables in Vercel. Use separate databases for previews and production, and configure the Prisma connection for the host.
    3. Apply the committed migrations to the target database with prisma migrate deploy in the deployment workflow before serving traffic that depends on the new schema. Make sure the build runs prisma generate, including on a clean install.
    4. Open the deployed URL and repeat a safe test with dummy data. Look for the expected database row and check the host’s logs if a request fails.

    Static option. For a brochure site or a preview with sample data, GitHub Pages can publish the static export. In the durian repo, npm.cmd run build:pages generates out/ and GitHub Actions publishes it. A live form on that static site needs an API hosted separately.

    Check The live URL serves the site and the feature works in the intended environment.

    Vercel GitHub deployments · Vercel environment variables · Next.js static exports · Prisma Migrate commands

File map

src/app/page.tsx and layout.tsx
The homepage and the shared layout. src/app/contact/page.tsx creates /contact.
src/components/, src/app/globals.css, public/
Reusable interface pieces, site-wide styles, and static assets such as images.
src/app/api/enquiries/route.ts
The backend endpoint for POST /api/enquiries.
src/lib/db.ts and src/lib/validation.ts
Server database access and rules for incoming data.
prisma/schema.prisma, prisma/migrations/, prisma.config.ts
The database models, saved SQL changes, and Prisma CLI configuration.
.env, .env.example, .gitignore
Local secrets, shareable placeholders, and the rules that keep secrets and generated files out of Git.
package.json and package-lock.json
Dependencies, runnable scripts, and the lockfile for repeatable installs.
next.config.ts and tsconfig.json
Next.js build settings and TypeScript compiler settings.
tests/, .github/workflows/, README.md
Tests, automated GitHub jobs, and setup instructions for the next developer.

Commands in your durian repo

Run these from the folder containing the durian app’s package.json. The database commands expect DATABASE_URL in your local .env.

npm.cmd install
Install dependencies and generate the Prisma client through the repo’s postinstall script.
npm.cmd run dev
Start the local Next.js server with live reload.
npm.cmd run db:deploy
Apply the migrations already saved in the repo to your configured database.
npm.cmd run db:seed
Add sample durian varieties to the development database.
npm.cmd test and npm.cmd run typecheck
Run the tests and verify types before pushing.
npm.cmd run build then npm.cmd start
Build the production app, then run that build locally.
npm.cmd run build:pages
Build the static GitHub Pages preview into out/.
